# Becoming the verifiably best agentic simulation-building environment

**Status:** active execution plan
**Started:** 2026-08-13
**Claim contract:** `tests/benchmarks/agentbench/preregister/v1/contract.json`
**Public instrument:** `agenticsimbench/verified-build-frontier-v0.1`

## 1. The objective

This programme exists to earn one narrow, falsifiable superlative:

> Under the frozen AgenticSimBench v1 protocol, the evaluated coding agents
> build a larger physically verified robotics-simulation frontier in OmniSim
> than in every primary comparison system, without a material cost penalty.

This is not a claim that OmniSim is the best simulator for every use case. It
is a claim about **agentic building**: one instruction, no human help, a running
artifact, and grader-owned physical evidence.

The binding comparison set is OmniSim, Isaac Sim/Lab, Gazebo, upstream Webots,
and Genesis. MuJoCo is an extended physics-engine arm because several
world-authoring tasks are not naturally expressible there. A missing primary
adapter or installation blocks the full claim; it may not be removed after a
bad result.

## 3. The frozen win rule

AgenticSimBench v1 uses two pinned coding-agent models, paired seeds, identical
task prompts and budgets, and each simulator's best first-party documented
workflow. Ordinary cells run five times. A1, R4, and every BuildScale endpoint
run ten times. A task is solved when at least 80% of its valid repetitions pass
all physical assertions.

OmniSim earns the scoped superlative only when all of these are true:

1. For **each model**, OmniSim's sum of claimable levels across the four
   existing tracks is strictly greater than every primary comparator's.
2. Against **each comparator and for each model**, OmniSim is no worse on at
   least three of four tracks and strictly better on at least two.
3. OmniSim's highest solved BuildScale level is no lower than any comparator's
   for either model and strictly higher than every comparator's for at least
   one model.
4. On matched tasks both systems solve, OmniSim's median normalized agent time,
   token use, tool calls, and provider-reported cost are each at most 1.25× the
   fastest simulator. Missing cost data cannot be silently treated as zero.
5. Every scored assertion has non-null red evidence; every scored
   `(task, simulator)` arm has oracle PASS and null FAIL.
6. An independent party reproduces the winning rank direction and at least 80%
   of task outcomes on at least one pinned model.

If any clause fails, “best” is withdrawn. We publish the narrower measured
result and fix the named bottleneck. The machine-readable contract is the
authority when this roadmap and code disagree.

## 4. Work programme

### Phase 1 — Freeze the claim before results

Deliverables:

- Machine-readable v1 claim contract.
- Human-readable claim and withdrawal statement.
- Hash manifest and a test that detects contract drift.
- A guard that refuses to regenerate the freeze after any v1 row exists.

Exit gate: the v1 contract test and the existing v0.3 freeze are green
together. No v1 scored row exists.

### Phase 2 — Make every grader capable of saying no

Build targeted negative fixtures for all 36 remaining assertions, starting
with the market-defining R1–R4 tasks. Each fixture must run through the actual
adapter and grader, commit a verdict, and fail for the predeclared physical
reason. Synthetic core-only evidence is diagnostic and does not close an
end-to-end gap.

Immediate fixture queue:

| task | negative evidence required |
|---|---|
| R1 | dirty run, missing/driveless robot, altered obstacles, missed goal, collision, teleport |
| R2 | dirty run, insufficient joints, wrong target order, teleport, ground penetration, timeout |
| R3 | dirty run, scene tampering, no real lift, never released, wrong destination, teleport |
| R4 | dirty run, collision, dropped payload, re-acquisition, false carry, wrong delivery, attachment cheat |
| remaining | A1 attribution; B2/B3 answer omissions; C2 dirty/fall-through negatives |

Exit gate: `preregister/v1/red_coverage.py --check` reports **61/61
validated**. **Complete 2026-08-13.**

### Phase 3 — Gate every simulator arm

For each supported `(task, simulator)`, prove oracle PASS and null FAIL. Add an
extra behavioural negative where a parked null cannot exercise the hard part,
such as R1 collision or R4 continuous carry. Unsupported tasks remain visible
capability gaps and stop the relevant contiguous frontier.

Exit gate: `preregister/v1/arm_gates.py --check` reports every one of the 50
primary cells READY or explicitly unsupported with a stable reason. Current:
**3 READY, 47 BLOCKED, 0 explicitly unsupported**.

### Phase 4 — Harden OmniSim using exploratory agents

Run fresh, unscored cells first. Classify each failure as model, tool, product,
grader, adapter, or infrastructure. Fix product/tool failures without changing
frozen prompts, thresholds, or graders. Every motion tool must return measured
`{commanded, achieved, error, settled}` values; no echoed command is evidence.

Priority product debt:

- reliable contact-rich manipulation and anti-attachment proof;
- honest sensors and actuation on the primitives used by campaign tasks;
- one-call task-level tools where primitive composition repeatedly fails;
- deterministic, recoverable world iteration and useful structured errors;
- artifact packaging that reopens without the authoring workspace.

Exit gate: OmniSim's oracle passes every supported task, and three consecutive
fresh exploratory campaigns expose no benchmark-blocking product/tool defect.

### Phase 5 — BuildScale: measure the claimed scale

Add simulator-neutral agentic authoring tasks at 10, 25, 50, 100, and 250
independently controlled robots. This is **not** bare solver FPS. The agent must
author the scene and controllers, place robots without interpenetration, make
the required fraction move, avoid runaway/collision failures, and produce a
portable artifact.

Record completion, controlled-robot count, path length, collision rate,
runaway count, agent time, tokens, calls, cost, startup/finalization time,
steady-state real-time factor, peak RAM/VRAM, and replay success. Each level
ships oracle, null, partial-control, overlap, teleport, collision, and runaway
fixtures.

Exit gate: all scale graders discriminate and at least two primary simulators
have runnable scale arms before comparative scoring begins.

Current implementation: the frozen spec, neutral core, synthetic
discrimination suite, exhaustive gate ledger, and real OmniSim + upstream
Webots and OmniSim levels 10, 25, and 50 are complete.
Remaining: real negative fixtures beyond the matched null, OmniSim levels
100-250, Webots levels 100-250, and the other primary adapters.
These gate measurements validate the instrument; they are not coding-agent
scores and do not yet support the market claim.

### Phase 6 — Fair primary comparator adapters

Implement clean staging, best-surface execution, evidence capture, grading,
and teardown for:

- upstream Webots;
- Isaac Sim/Lab;
- Gazebo;
- Genesis.

MuJoCo remains an extended arm. Adapter authors may not weaken a competitor by
omitting a documented first-party workflow. Each adapter publishes its tool
surface, exclusions, install image/digest, versions, and oracle evidence before
scored model runs.

Exit gate: the same neutral oracle contract passes on every expressible arm.

### Phase 7 — Run the frozen campaign

Use fresh answer-key-filtered workspaces and ephemeral agent sessions. Pair and
interleave simulator order by seed; never run paired cells concurrently on the
same host. Preserve every prompt, event stream, workspace, final artifact,
grader record, video, simulator log, model/CLI identity, hardware fingerprint,
and failed or timed-out attempt.

Exit gate: the full matrix is present, contamination checks are clean, invalid
cells are at most 20%, and the v1 evaluator emits a win or withdrawal verdict
without operator judgment.

### Phase 8 — Independent reproduction and Evidence Arena

Give the frozen suite to an outside robotics engineer or lab. After the
correction window, publish a page per cell with prompt, artifact, playback,
measurements, cost, failures, caveats, and one-command rerun instructions.

Exit gate: independent reproduction satisfies clause 6 of the win rule.

```powershell
  agentbench.preregister.v1.test_build_scale_freeze `
  agentbench.preregister.v1.test_build_scale_gates
```

Fresh Codex campaign entry point:

```powershell
python tests/benchmarks/agentbench/codex_lane/run_codex_campaign.py `
  --sims omnisim,webots `
  --tasks frontier `
  --model <exact-model-id> `
  --root <disposable-staging-root> `
  --out <new-evidence-directory>
```

Standing rules:

- No row, no result.
- No red evidence, no score.
- No oracle/null gate, no simulator arm.
- No preserved artifact, no pass.
- No post-result comparator removal or threshold change.
- Exploratory builders may inspect graders; scored builders may not.
- Published vendor figures are citations, never measurements made by us.
- A failed win rule produces a withdrawal, not a rewritten benchmark.

## 7. External baselines that shape the plan

The comparison must confront competitors at their strengths. Isaac Lab
publishes reproducible runtime/training benchmark scripts and results across
thousands of environments:
<https://isaac-sim.github.io/IsaacLab/main/source/overview/reinforcement-learning/performance_benchmarks.html>.
Gazebo documents broad physics, rendering, sensor, plugin, transport, and CLI
surfaces: <https://gazebosim.org/libs/sim/>. MuJoCo includes soft objects,
tendons, muscles, multiple solvers and integrators: <https://mujoco.org/>.
Genesis publishes performance comparisons and scripts:
<https://github.com/Genesis-Embodied-AI/Genesis>.

Those strengths are why the headline is verified agentic build outcome and
scale—not a vague feature count or incomparable vendor FPS.
