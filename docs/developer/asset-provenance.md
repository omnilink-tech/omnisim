# Media Asset Provenance Ledger

**Status: remediation pass of 2026-08-22. This file travels with the public snapshot; git history does not.**

> **Why this file exists.** Public releases are published as a **single squashed
> commit per version**, so a reader of the published repository cannot run
> `git log --diff-filter=A` on an asset to find out where it came from. Every
> provenance conclusion in this repository that rests on git evidence would
> therefore be unverifiable — and unreproducible — the moment it shipped. This
> ledger carries the conclusions, and the evidence behind them, in-tree.
>
> **Scope.** The 2026-08-22 pass covered image, audio and mesh assets in the
> directories listed below. It is **not** a whole-tree audit — and §1 is not the
> whole ledger any more: a **second pass on 2026-08-24**
> ([§6](#6-second-pass-2026-08-24--what-the-2026-08-22-pass-could-not-see))
> widened the extension set, which surfaced 22 uncovered files the first pass
> was structurally unable to see plus **both of the tree's BSD-3-Clause
> third-party asset sets**, previously absent from every ledger. The broader IP register —
> robot packages, PROTO `# license:` headers, fonts, vendored code, blockers —
> is [`third-party-licenses.md`](third-party-licenses.md), and the legally
> operative attribution file is the repository-root `NOTICE`. Where this file
> and those disagree, see [§4](#4-corrections-owed-to-files-outside-this-pass):
> this pass found several places where they are now wrong.

## 2. Open items, ranked

### A. `Helmet.proto` — declared MIT, upstream says CC BY-NC

Full evidence and the two tests that would settle it:
[`projects/samples/rendering/protos/PROVENANCE.md`](../../projects/samples/rendering/protos/PROVENANCE.md).

Short form: there is **no reading of the evidence under which the current state
is correct**. If our copy descends from theblueturtle\_'s 2016 model it is
CC BY-**NC**, which cannot ship inside an Apache-2.0 distribution at all — the
same defect that removed `FireExtinguisher.proto`. If it descends from ctxwing's
2018 CC BY 4.0 rebuild it is shippable, but CC BY 4.0 §3(a) requires an
attribution that appears **nowhere** in this repository. One world uses it
(`projects/samples/rendering/worlds/physically_based_rendering.omniworld`), so
the blast radius of removal is one PBR demo mesh.

**`projects/objects/telephone/protos/Telephone.proto` carries the identical
`# license: MIT` header and the identical citation.** It is the *other* of the
two PROTOs that `NOTICE` counts as MIT. It was outside this pass's file
ownership and **has not been investigated**. It needs the same check.

### B. `suzanne.obj` — a GPL-sourced coordinate table inside an Apache-2.0 tree

Full record: [`projects/default/worlds/meshes/LICENSE.txt`](../../projects/default/worlds/meshes/LICENSE.txt).

The file is a **verbatim** export of Blender's built-in Suzanne (507 verts /
500 faces — the primitive exactly), whose vertex data is embedded in Blender's
GPL-2.0-or-later source. Whether an export of a primitive is a "work based on"
that source is a legal question, not an engineering one, and both readings are
arguable. It is recorded here, not decided.

**This is a gap the existing copyleft audit could not have caught.**
`third-party-licenses.md` §5 concludes the tracked tree "contains no
GPL/LGPL/AGPL/MPL-licensed file" — from a scan for **licence text and SPDX tags
inside files**. A mesh has neither. The scan is not wrong about what it measured;
it is structurally blind to assets that carry a licence only by derivation.
**Any re-run of that scan should state that limit explicitly.**

### C. `san_giuseppe_bridge_4k_*` — probably CC0, not proven

Full record:
[`scripts/icon_studio/worlds/textures/cubic/LICENSE.txt`](../../scripts/icon_studio/worlds/textures/cubic/LICENSE.txt).
A filename is not a chain of title. Cheapest resolution is not proving it — it is
repointing `icon_studio.omniworld` at the `studio_*` gradient set already sitting
in the same directory.

### D. `cow.wav` — no metadata at all

Full record:
[`projects/samples/devices/controllers/speaker_text_to_speech/sounds/LICENSE.txt`](../../projects/samples/devices/controllers/speaker_text_to_speech/sounds/LICENSE.txt).
An animal sound effect is the asset class most often taken from a free
sound-effect library, where CC BY (attribution required) and CC BY-NC
(incompatible) are the usual terms. Decorative; one clause of one demo sentence.

## 5. Method — how to extend this ledger

1. **Read the asset's own bytes first.** It is the only evidence that survives a
   squashed release. WAV `LIST/INFO` + ID3 chunks, PNG `tEXt`/`iTXt`/`zTXt`,
   JPEG EXIF / XMP / Photoshop-IRB, FBX `SceneInfo` properties, OBJ and Radiance
   headers. Five of this pass's conclusions came from there and nowhere else.
2. **Then `git log --diff-filter=A --follow`.** In this repository it can only
   ever say "arrived in the squashed import `0db6a18a7`" — useful as a boundary,
   never as authorship.
3. **Use the shape of the content.** Unique-colour counts separate a photograph
   (10<sup>4</sup>–10<sup>5</sup>) from synthetic artwork (10<sup>2</sup>–10<sup>3</sup>).
   Vertex and face counts identify a verbatim primitive. Both settled a question
   here that metadata could not.
4. **Absence of a notice is evidence only when scoped.** "Upstream attached a
   third-party notice to *these* directories and not *that* one" is an argument;
   "there is no notice" alone is not.
5. **Prove orphanhood before deleting** — path greps *and* basename greps *and*
   a read of the code that would consume it — then re-run the affected worlds
   headless afterwards. Both deletions here were verified both ways.
6. **Never upgrade "indicated" to "established".** A filename, a plausible
   vendor, or a licence that a *sibling* asset carries are all indications. Say
   what would settle it instead.

## 6. Second pass, 2026-08-24 — what the 2026-08-22 pass could not see

The pass above walked **image, audio and mesh** assets. It was bounded by the
same thing the provenance gate is bounded by: an **extension list**. Re-running
the gate's own classifier over a widened extension set
(`.npz .svg .pdf .mp4 .ico .exr .npy .gif` on top of `ASSET_EXTENSIONS`) turns up
**22 tracked files that no licence file covers and no `OWN_WORK` entry claims** —
files the gate is structurally unable to fail on, so their absence from the
ledger was never going to surface as a red build.

None of the 22 turned out to be third-party. That is the *outcome*, not the
*reason to have looked*: an audit that only inspects the categories it already
has a rule for cannot discover a category it lacks a rule for.
