# T2 (put a block in a bin, hold it 10 s) — the column, 2026-08-04

Internal sounding. **Not a publishable benchmark result**: n=1 per cell, one
machine (`9722d23d12a3`), one model family, and one of the three columns is not
built. Every number below is a single run.

## The column

| column | wall clock | tool calls | verdict | the failing clause |
|---|---|---|---|---|
| **omnisim** best | **27.1 min** | **48** | 4/5 | T2.2 — **ours** (see below) |
| **omnisim** clean | 51.2 min | 100 | **PASS 5/5** | — |
| **mujoco** | **19.9 min** | 54 | 4/5 | T2.2 — **real**: carried clear 1.55 s of a required 3.0 s |
| **webots** | — | — | **NOT-BUILT** | the column cannot answer T2's channels |

Both graded columns land on 4/5 and both fail T2.2, **for entirely different
reasons**, which is the single most important thing on this page:

- **MuJoCo's is a measurement.** It lifted the block to 0.1719 m with a genuine
  friction grip (`hold_mechanism: friction`) and held it clear for **1.55 s**
  where the tier asks 3.0 s. That is a finding about the run.
- **Ours is an unanswered channel.** The agent's world declared **no floor** —
  Newton supplies an implicit ground plane at z=0 that is not a node — so
  "what was the object resting on" had no answer and the clause could not be
  graded. Fixed on 2026-08-04 (`a7739b98`): a world with no static collision
  surface now warns that it is not self-describing. **The 27-minute run has
  not been repeated since that fix**, so whether it reaches 5/5 is untested.

## Why webots is NOT-BUILT, precisely

The column exists and works: AgentBench's launcher runs upstream Webots R2025a
headless inside WSL2, and the ladder shim converts its recorder output into the
shared pose-series CSV. That is everything **P1** needs.

T2 needs six channels. The shim answers one.

| channel | webots status |
|---|---|
| `roles` | task data — free |
| `object_pose` | **have it** (the pose series) |
| `end_effector_pose` | needs orientation as well as position |
| `container_geometry` | needs a world-space subtree AABB and a measured rim |
| `object_mass` | needs the `Physics` mass and `WorldInfo.gravity` |
| `grip` | needs contacts **and** a mechanism citation |

It is all-or-nothing: a partial surface makes its dependent assertions
unanswerable, which grades as `scaffolding_defect_ours` and measures nothing.
So a half-built column is worth exactly as much as no column, and costs a cell
to discover.

**Scope to close it:** a Webots supervisor recorder writing the
`omnisim_ladder_channels/v1` schema — roughly a port of the T2 subset of
`ladder/controllers/ladder_recorder/`. Every channel is reachable through
Webots' supervisor API. One is genuinely harder: **the grip MECHANISM.**
MuJoCo can prove friction rather than attachment by reading `mjModel.neq` and
the equality table; Webots has no equivalent, and a kinematic weld there is a
supervisor writing a position every tick, which is not introspectable from the
model. So `grip` on that column will likely have to report the mechanism as
`unknown` and justify it, rather than attesting friction the way the other two
can. That is a real difference between the products and belongs in the result
rather than being smoothed away.

## Instrument defects found and fixed while measuring this

Recorded because each one had, at some point, produced a wrong verdict:

| defect | effect before the fix |
|---|---|
| a session that ran was filed `launch_failed` | two results lost their metrics and their deliverable |
| `phase_b_broke` read an attribute only one column has | **every** MuJoCo cell filed as our scaffolding — a fairness bug in our favour |
| the driver had to be named `drive.py` | a working MuJoCo scene stepped with `ctrl_writes: 0` |
| screenshots returned an unrendered buffer | ~16 min of one run, and nearly false visual evidence |
| the container staged empty | an agent solved the task in the wrong simulator |
| our own findings docs staged as workspace files | would have handed a later agent the answer |
