## Author a world

**User asks for:** **Author or edit a world (`.omniworld`)**

**Your first move:** ⚠️ **The world extension is `.omniworld`, not `.wbt`** — see the dual-read rule below before you name a new file. Start the harness: `python -m omnisim harness`. Load with **`POST /world/load {"path": ..., "light": true}`** — ⚠️ **without `light` the harness is SLOWER than just re-running `run-headless`** (measured: a reload costs **13.4 s** vs 6.37 s headless, and stepping can cost seconds per step; see the harness rule below). After every edit use **`POST /world/sync` by default**: it live-applies only proven root-DEF pose changes and automatically hot-reloads every other edit. That is where the loop is won — measured on the cloth world, a pose-only root-DEF edit lands in **325 ms** (`mode: live_pose`) and a structural one in **2818 ms** (`mode: full_reload`), against a 6.37 s headless floor. Then `GET /scene/tree`, `GET /world/render_stats`, `POST /world/screenshot`. Full loop: §5.

## Gripper grasp

**User asks for:** **Make a gripper HOLD something** (pick-and-place, a pinch grasp, carrying a part)

**Your first move:** ⭐ **Read [docs/guide/friction-grasp.md](../../docs/guide/friction-grasp.md) FIRST — most defaults still do not hold a grip and the reasons are not guessable.** The solver is no longer one of them: since 2026-08-07 the default `newtonSolver` **is** `"mujoco"` (XPBD, which structurally cannot hold a static pinch, was removed the same day — a world still declaring `"xpbd"` gets a warning and the default). Still required: `newtonGroundMu` (⚠ `WorldInfo.contactProperties`/`coulombFriction` was the **ODE-path** friction declaration and it is **not read** — `newtonGroundMu` is the field that sets contact friction; the engine warns when a world declares the old one), firmer `newtonContactKe`, an elliptic cone + `newtonImpratio`, and `basicTimeStep 8`. In the controller: ⚠ **`setForce` does NOT put a Newton joint in force mode** — the joint is built `POSITION_VELOCITY` with `targetKe = effortLimit * 10`, so the PD servo stays live anchored at the last `setPosition` and a "25 N squeeze" is really a spring pulling ~20 mm INSIDE the part; it buries the pads and launches the part on lift. Use a **position target with a known interference** (kp is `effortLimit * 10`, so 3 mm of bite is a few N), or set `OMNISIM_NEWTON_TORQUE_MODE=1` for real force mode. ⚠ **`friction_grasp_minimal.omniworld` is NOT a working grasp** — measured 2026-08-10, its part is ejected at 3.5 m/s and lands on the gripper's wrist plate, and its own test cannot tell a carry from a tray. The runnable example that does hold, and ships a drop control: `python -m omnisim run-headless projects/samples/demos/worlds/flagship/omniarm6_real_pick_place.omniworld --duration 45` (`PICK_CONTROL_DROP=1` must leave the block behind). `getContactPoints` reads native Newton contacts by default since 2026-08-07, but still prove a grasp geometrically (the part is airborne and tracks the gripper) — a contact read is a weaker claim than a lifted part.

## Many worlds load

**User asks for:** **Test that MANY worlds load** (a sweep, a corpus, CI smoke)

**Your first move:** ⭐ **`python scripts/dev/batch_validate.py <worlds...>`** — one engine process, hot-reloading each world, instead of N fresh engines. Measured on 19 worlds (machine `9722d23d12a3`): **174 s → 34.6 s (5.0×)** at `-j4`, 9158 → 1822 ms/world. The ladder: `-j1` 70.7 s, `-j2` 49.4 s, **`-j4` 34.6 s**, `-j6` 36.9 s — **`-j6` is already slower**, because each engine is a whole process (~1 GB resident) so RAM/disk/GPU contention binds long before the 16 cores do. ⚠️ **It also avoids the engine startup race**: the fresh-process baseline scored 18/19 while every reuse configuration scored 19/19, and on an earlier 10-world corpus back-to-back spawning FAILED 3 of 10 — all three PASS individually (the documented "roughly one launch in three"). ✅ **That race is ATTRIBUTED and FIXED in the engine as of 2026-08-29, and it was never Qt's** — see the "Run K worlds in parallel" row and §3e: a Windows engine given a stdout that was not a pipe used to attach to its launcher's console and could find its fd 1 dead by the time the embedded interpreter wrote to it (EBADF out of `newton.ModelBuilder()` → FATAL → exit 1); it now keeps whatever stdout it was given. `batch_validate.py` is still the faster way to sweep a corpus; it is no longer the only way to sweep one *reliably*. Same strictness (both it and `run-headless` FAIL a bad EXTERNPROTO and an undeclared node), and it reports the harness's structured diagnostic codes rather than a scraped log. `-j N` for parallel engines, `--from-file` / `--glob` for a work list, `--json` for machine-readable results. LOAD check only — see the row below for the caveats it shares.

## One world loads

**User asks for:** **Test that a world loads**

**Your first move:** ⭐ **`python -m omnisim run-headless <world> --until-finalized --fail-on-warning`.** Use `--until-finalized` on every load check: `--duration` is a wall-clock **sleep**, not a progress target, so a run costs whatever number you guessed — and the standing "budget ≥15 s, ≥45 s on cold/virtualised disks" advice exists only because a run that ends before finalize writes no sidecar. The real wait is far shorter (measured, machine `9722d23d12a3`: **3985/4088 ms** cloth, **5419 ms** 8-Husky swarm), so the flag stops the run the moment Newton finalises and the sidecar exists: **15.52 s → 6.37 s, and 45.34 s → 6.37 s (7.1×)**, same `PASS`, same sidecar. Non-zero exit on load failure. ⚠️ A PASS means "loaded, stepped, logged nothing bad" — **not** "the physics is sane": a body free-falling through a floor with no `boundingObject` also passes. `--until-finalized` proves **load + finalize only**; keep `--duration` when the run must *observe* behaviour, and add `--fail-on-runaway` to certify a *physics* fix (§3b).

## OmniBench

**User asks for:** **Benchmark physics, throughput, or "how does OmniSim compare?"**

**Your first move:** ⭐ **OmniBench** — [`tests/benchmarks/omnibench/`](../../tests/benchmarks/omnibench/), contract in [`SPEC.md`](../../tests/benchmarks/omnibench/SPEC.md), one entry point `python tests/benchmarks/omnibench/run_all.py` (add `--parallel 6` on Linux). Three lanes: **correctness** vs analytic ground truth (7 scenes × dt sweep × mujoco / pybullet / omnisim-newton, one harness), **throughput** three-tier per the post-Genesis credibility checklist (contacts ON, actions never idle, machine-attributed), and **determinism / train==deploy parity / agent-driveability**. Latest campaign + all caveats: [docs/benchmarks/omnibench-2026-07-24.md](../../docs/benchmarks/omnibench-2026-07-24.md). ⚠️ **Read every ODE row in that campaign as HISTORY.** ODE was deleted in `bdc02139` (2026-08-08) and its lane-1 arm no longer runs; the campaign's ODE columns are what they measured on the date they name, not a backend you can re-run today. **Three things to carry forward:** (1) **There is no second IN-ENGINE path to cross-check the plumbing — which is NOT the same as "no oracle", and the difference matters.** Lane 1's oracle is **analytic ground truth** and it is untouched; bare `mujoco` and `pybullet` still run as external arms. ⚠️ **The claim to stop repeating is "ODE was the accuracy reference and we lost our accuracy".** Through 2026-07-24 `omnisim-ode` was best or tied-best on 6 of 7 scenes at dt=4 — but that compares **two integrations, not two solvers**, and the campaign's own lane-1 headlines say so: *"raw mujoco(-warp) scores fine on the same scenes with the same solver family, so these live in our Newton integration layer."* The four defects behind Newton's deficit (friction cone, rolling inertia, momentum leak, spin loss) were **ours** and were **all fixed in `e7b9fb11`**. ODE's values are **frozen** in [`tests/goldens/ode_oracle_goldens.json`](../../tests/goldens/ode_oracle_goldens.json) as a fixed regression datum. So what the deletion cost is the ability to run one `.wbt` through two integrations and tell "the solver got this wrong" from "we handed the solver the wrong model" — the instrument that caught gravity never being plumbed. ✅ **That gap is now CLOSED by a different instrument (2026-08-09): [`lane1/translation_audit.py`](../../tests/benchmarks/omnibench/lane1/translation_audit.py)** compares the `.wbt`'s authored contract against the exact mjModel the solver stepped (`OMNISIM_NEWTON_DUMP_MJMODEL`) — gravity magnitude *and* `coordinateSystem` up-axis, timestep vs substeps, per-geom friction and `condim`, masses, collidability, and every declared-but-unread field. It beats the ODE diff on the same question (a two-backend diff says the two *disagree*; the audit names which side is wrong) and needs one engine. `--self-test` proves it can go red before you trust its green. On its first corpus run it found that the lane-1 worlds **were not self-describing** — they declared `coulombFriction 0.5/0.8` while the model ran μ=1.0, the real value arriving only via the runner's env var — now fixed by declaring `newtonGroundMu`/`newtonContactKd` (measurements verified bit-identical).
