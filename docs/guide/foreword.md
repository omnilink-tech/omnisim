## Foreword

OmniSim is more than a 3D robotics simulator: it is **an open-source robotics workshop for agents**, a place where an agent has everything it needs to work on any robotic system — simulate one on high-fidelity physics, build the digital twin of a robot you already own, connect it to the real machine, and program, test and debug the result while you talk to it. The goal is to make robotics accessible to anyone with an idea, including the many people who have one but no access to the hardware.

The workshop's deepest bench is the one for finding out what a robot actually did, and its guiding principle is simple: **an instrument that lies is worse than no instrument.** Robotics has almost no observability; a simulator that reports a confident answer it cannot support is worse than one that admits the gap. So `GET /sim/contacts` returns what it walked plus a `completeness` field and `empty_set_reasons[]`, never an empty list sold as "no contact"; `GET /capabilities` publishes what the simulator refuses to do, with a reason and a workaround per gap; `--fail-on-runaway` FAILs rather than passes when the evidence is too thin to certify; and the live event-type list is generated by scanning the code's own emit sites, so documentation drift is reported rather than believed.

Claude Code (or another coding agent) builds and iterates on the simulator and its worlds; OmniLink (or another runtime client) drives them. The canonical statement of what OmniSim is — and the measured limits on what may be claimed for it — is [`docs/developer/positioning.md`](../developer/positioning.md).

OmniSim is a fork of [Webots](https://github.com/cyberbotics/webots), an open-source 3D mobile robot simulator originally developed as a research tool to investigate control algorithms in mobile robotics. Webots has been released under the [Apache 2.0 license](https://www.apache.org/licenses/LICENSE-2.0) since December 2018; OmniSim inherits that license, along with the world-file format, the controller API, and the PROTO system. Where this user guide still refers to "Webots" (it was inherited from the upstream manual), the underlying behaviour generally applies to OmniSim as well.

This guide will get you started using OmniSim. It assumes a minimal working knowledge of mobile robotics, of C, C++, or Python programming, and of the VRML97-derived world description language used for `.wbt` files.

We hope you enjoy working with OmniSim.
