# Connect OmniLink to a robot in OmniSim

OmniSim is the free, open-source robotics workshop. OmniLink is the connected AI agent. Every OmniLink session requires an OmniKey and a model connection, including on the Free plan. Provider usage is billed separately.

[Watch the featured Husky demo](../media/omnilink-husky/omnilink-husky-live-ai.mp4) · [Recording notes](../media/omnilink-husky/README.md).

## Set up your account

Open https://www.omnilink-agents.com/agents/start, sign in, and connect a supported model provider. Your OmniKey identifies your OmniLink account. Your provider key stays in OmniLink; do not put it in a robot world or source file.

## Launch a robot

Windows has the prebuilt OmniSim package. Linux requires a source build. From the OmniSim directory, run the doctor check and proceed only when its verdict passes.

PowerShell:

```powershell
.\omnisim.bat doctor --omnilink
$env:OMNI_KEY = 'YOUR_OMNI_KEY'
$env:OMNILINK_ENGINE = 'g1-engine'
$env:OMNILINK_MODEL = ''
.\omnisim.bat run-world projects/samples/demos/worlds/chat/omnilink_husky.omniworld
```

Linux shell:

```sh
python -m omnisim doctor --omnilink
export OMNI_KEY='YOUR_OMNI_KEY'
export OMNILINK_ENGINE='g1-engine'
export OMNILINK_MODEL=''
python -m omnisim run-world projects/samples/demos/worlds/chat/omnilink_husky.omniworld
```

The example selects Google. The onboarding guide generates commands for your selected provider. Local models must also connect through OmniLink with an OmniKey and the configured local-model connector; there is no automatic keyless model mode.

## Dependencies for source checkouts and older packages

The prepared Windows bundle includes the public OmniLink SDK, HTTP/TLS
transport and image dependencies. No private OmniLink checkout is needed.
Linux's source bootstrap installs the same dependency lock into the controller
interpreter. Existing downloaded packages do not acquire these changes until
updated.

For a source installation, install the lock using the Python that runs your
controllers:

```sh
python -m pip install -r scripts/packaging/requirements-omnilink.txt
python -m omnisim doctor --omnilink
```

On Windows, controllers use the bundled interpreter. Installing into system
Python alone will not repair an older bundle; use the
[bundle repair instructions](../developer/newton-runtime-bundle.md#one-controller-interpreter-on-windows-resolved-2026-09-22).
A passing dependency check does not validate your OmniKey or provider account.

## Reproduce the featured sequence

The featured recording used `g3-engine` with the provider-selected model
(`OMNILINK_MODEL` empty). Select that engine with the corresponding provider
connected, or use the engine generated by your onboarding setup. In a fresh
Husky session, ask it to remember the starting position as base, drive a
one-metre square, change the square's size and direction, navigate to a
midpoint, report its distance from base, then return. Wait for each instruction
to finish and inspect the reported measurements. Model decisions and timings
can vary; the film removes waiting and compresses motion.

## Give an instruction

Right-click the robot and choose **Show Robot Window**. When OmniLink is configured, send an instruction such as “Drive forward one meter, turn around, and tell me what you did.” Read the returned result before continuing.

Without a connection, the chat panel shows a setup link. Missing keys, failed authentication, missing provider credentials and model failures are errors, not a switch to basic command handling. A configured connection is not proof that provider access is valid: the first successful response confirms that.

## Ordinary simulator controls

OmniSim's typed control API and Stop button remain available without an OmniKey. These are simulator controls, not an OmniLink agent. For a mobile robot bridge on port 8765:

```powershell
Invoke-RestMethod http://127.0.0.1:8765/drive_forward -Method Post -ContentType application/json -Body '{"distance":1,"wait":true}'
Invoke-RestMethod http://127.0.0.1:8765/stop_robot -Method Post -ContentType application/json -Body '{}'
```

Use the direct Stop control when needed; it does not depend on model availability. These direct controls retain their existing simulator semantics and are not an OmniLink safety certification.

## Scope

The demonstrations run in simulation. A model's reply is not proof of physical motion: use the robot's reported state and measurements. No physical-hardware performance is established by the demo video. Humanoid demonstrations may use a weight-bearing balance harness.

Existing downloaded versions retain their old behavior until updated. Removing the keyless product flow does not retract previously published source or make client-side code confidential.
