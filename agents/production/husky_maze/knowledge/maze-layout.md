# Maze layout — husky_maze worlds

Two world files share the same coordinate convention and are both driven by the same agent + bridge. The agent picks its strategy from `capabilities.map_available`, which the bridge derives from `WorldInfo.title`.

## Geometry (both worlds)

- 11 x 11 cell grid, each cell 2 m x 2 m.
- World extent: x in [-11, +11], y in [-11, +11] (22 m square interior).
- Cell `(col, row)` centre: `world = (-10 + 2*col, -10 + 2*row)`.
- Indexing: `col = 0..10` west→east, `row = 0..10` south→north.
- Outer perimeter is four `wall_perim_*` walls (height 1 m).
- Husky spawn: cell `(0, 10)` at world `(-10, +10)`, drop height `0.1 m`, facing east (`yaw = 0`).
- Goal: cell `(10, 0)` at world `(+10, -10)`. Marked by a red post + yellow sphere `Solid` named `goal_marker`. `goal_reached` flips true within `0.8 m` of the goal centre.

## The two worlds

| File | Title (in `WorldInfo`) | Seed | `map_available` (via bridge) | What the agent does |
|------|------------------------|------|------------------------------|---------------------|
| `projects/samples/demos/worlds/flagship/husky_maze.wbt` | `Husky Maze` | 7 | `true` | Strategy A: BFS over `try_get_known_map` adjacency |
| `projects/samples/demos/worlds/flagship/husky_maze_unknown.wbt` | `Husky Maze (Unknown)` | 19 | `false` | Strategy B: `read_lidar` + right-hand-rule wall-follow |

The bridge gates `/maze` on `"unknown" in title.lower()`. Authoring another "unknown" world is just running the generator (see `agents/production/husky_maze/scripts/generate_maze_world.py`) with a fresh seed and a title that includes the word "Unknown".

## Wall convention

Both worlds are **perfect mazes** generated by recursive backtracker (DFS): exactly one path between any two cells, plus side dead-ends. 121 cells, 120 internal edges.

- **H-wall** (`H_NNN`, `size 2 0.2 1`): runs along x. Located at world `(x = -10 + 2*col, y = -9 + 2*row_lo)`. Blocks the passage between cell `(col, row_lo)` and cell `(col, row_lo + 1)`.
- **V-wall** (`V_NNN`, `size 0.2 2 1`): runs along y. Located at world `(x = -9 + 2*col_lo, y = -10 + 2*row)`. Blocks the passage between cell `(col_lo, row)` and cell `(col_lo + 1, row)`.

The bridge collects every `Wall` node from the supervisor at startup, so adding more walls to a world or generating a new layout works without code changes.

## Adjacency at runtime

Don't hard-code the path here. Either:

- **Known-map case** — call `try_get_known_map`. Bridge returns `{available: true, adjacency: {"col,row": [[c,r], ...]}, start, goal, ...}`. Run BFS from `world_to_cell(state.x, state.y)` to `goal`.
- **Unknown-map case** — `try_get_known_map` returns `{available: false}`. Use `read_lidar` to determine which 4-neighbour cells are open, then pick a direction (right-hand rule for guaranteed-solvable perfect mazes).

## Failure modes

- **Wedged against a wall**: usually because the husky drifted during a pivot and ended up straddling a wall edge. Recover with `stop_husky` → `snap_to_cell` to the last-known-good cell with the right yaw → resume.
- **Off-corridor drift**: if the husky drifts more than 0.5 m off the row/column centerline two ticks in a row, snap back to the cell.
- **Goal radius**: 0.8 m around `(10, -10)`. Don't keep commanding cells once `state.goal_reached` is true.

## Source of truth

The walls are listed in the world `.wbt` files. The bridge parses them at startup; the agent never reads the `.wbt` directly. If the world changes, the bridge picks it up on next `/admin/reload`.
