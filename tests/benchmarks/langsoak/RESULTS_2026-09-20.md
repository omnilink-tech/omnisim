# Language endurance — 2026-09-20

**3,071 utterances · 64 held-out wordings · ~48 passes each · 2.00 hours · 0 tokens**

```
python tests/benchmarks/langsoak/run.py --hours 2
python tests/benchmarks/langsoak/analyse.py --lang tests/benchmarks/langsoak/langsoak_2h_2026-09-20.json
```

Machine: AMD Ryzen 7 5800H, 32 GB, Windows 11. `omnilink_husky_langsoak.omniworld`
on bridge port 8775, run beside the endurance soak on 8765. No `OMNI_KEY`,
so no model was in the loop at any point — asserted, not assumed.

> Every sentence here is **held out**: none appears in `commandbench`, whose
> own header notes its cases "were written by the author of the parser under
> test". Re-running those measures regression. This measures understanding.

## Headline

| | |
|---|---|
| accuracy (known gaps excluded) | **78.2%** |
| accuracy excluding a bad test case of ours (below) | **~79.9%** |
| **false actuations** | **432 — 22.0% of 1,968 STILL cases** |
| missed commands | 96 (10.5% of 911 MOVE) |
| wrong motion | 52 |
| bridge-busy refusals | **0** — the confound we feared did not occur |
| **accuracy drift over 2 h** | **78.2% → 78.1%** |

## Two findings that matter more than the percentage

### 1. Interpretation does not rot

Two hours of continuous conversation, with the surface accumulating memory
writes, standing policies, holds and a journal throughout. Accuracy moved
**one tenth of a point**. Nothing degraded, nothing became state-dependent.

This was the question the benchmark was built to ask, and nothing in the
project had measured it. A parser correct on a clean robot could have been
wrong on one talked to for an hour. It isn't.

### 2. The failures are deterministic, not flaky

**Thirteen of the fifteen failing utterances failed 48 times out of 48.**
Only two were intermittent, both at 4.2% (`comp-a1`, `unit-a3`).

That is a categorically different maintenance problem from a model that is
wrong a fifth of the time unpredictably. These are missing rules: findable,
reproducible, and each fix stays fixed. You can enumerate this failure set;
you cannot enumerate a model's.

**336 of 336 questions left the robot still.** The keyword ladder this

containing a motion verb, in a wording nobody tuned for.

## Where it is broken — four concepts, not fifteen bugs

| family | | failing cases | the concept |
|---|---|---|---|
| quote | **0.0%** | `a1` `a2` `a3` — 144/144 | ignores the clause that governs the imperative |
| contra | **0.0%** | `a1` `a2` — 96/96 | first direction wins; no contradiction check |
| retract | 33.3% | `a1` `a2` | retraction is a phrase list |
| neg | 66.7% | `a1` `a5` | prohibition is a phrase list |
| noise | 66.7% | `a6` | bare trigger invents a magnitude |
| comp | 47.9% | `a2` | two motions that cancel: did nothing |
| base | 87.5% | `a3` | "advance" is not a known verb |

### The diagnosis, in one line

**Every guard is a finite list of surface forms, not a concept.** The
cleanest proof is inside one family: `retract-a3` ("scratch that") **passes**
while `retract-a1` ("sorry, ignore that") and `retract-a2` ("no, make it
left") fail 48/48. Same concept, three wordings, one on the list.

Likewise prohibition — "avoid", "hold off on" and "must not" are all
recognised, while "under no circumstances" and "refrain from" are not.

`interpret.py`'s own docstring says the defect it exists to fix is that
**"matching a substring is not interpreting an utterance."** On these cases
tier 0 is still surface-matching: the ladder matched keywords to *fire*
actions, tier 0 matches keywords to *suppress* them. Both fail on sentences
nobody enumerated. It is markedly better — 100% on every question, every
hypothetical, every deferred order — but it has not changed the failure
*kind*, only its frequency and its direction.

### Inventing a magnitude

`noise-a6` is the bare word `"forward"`, and it drives 1 m — the reply says
*"Driving forward 1 m by default"*. The same default fires inside `neg-a1`.
A surface that refuses an underspecified order is safe; one that invents a
number is not. This is the same class as the units bug where `"two metres"`
drove exactly 1.000 m.

## A bad test case of ours

`noise-a5` is an empty string, and all 48 of its "errors" are the bridge
correctly rejecting empty input with an HTTP error. The robot did not move,
which is what the case asked for. Scoring that as a failure is our bug, not
the product's, and it is the whole of the `errors` column.

## What this does NOT show

- **Not representative traffic.** These are adversarial held-out cases, like
  `commandbench`. The coverage number for real traffic comes from the
  production export (OmniLink's deterministic-core plan, Phase 0), not here.
- **Not a model comparison.** No model was run against this corpus. Whether
  an LLM scores better than 78.2% on these same sentences is unmeasured, and
  it is the obvious next experiment.
- **Not hardware.** Simulation only.
- **One robot, one surface** (MOBILE). The arm, quadruped and drone bridges
  were not exercised.

## Implication for the cost thesis

The thesis claims *"false positives on non-command prose: 100% → 0%"*. That
0% is honest for the 178-utterance corpus it was measured on, and **it does
not generalise**: on held-out wordings, 22% of STILL cases actuate.

The claim that does survive, and is stronger for being narrower: the
deterministic core is **perfect on every question, hypothetical, deferred
order, unbound reference, social probe and safety bound it was shown** —
1,248 for 1,248 — and where it fails it fails the same way every time, for
$0.00 and with no model in the loop.

# Re-measured on the GATED path — 2026-09-21

Everything above was measured before the safety gate was wired onto the
paths the product actually uses. This is the same corpus, same judge,
same robot, after wiring it.

| | ungated (2026-09-20) | **gated (2026-09-21)** |
|---|---|---|
| accuracy | 78.2% | **91.7%** |
| **false actuations** | **432 of 1,968 STILL = 22.0%** | **13 of 540 = 2.4%** |
| drift over the run | 78.2% → 78.1% | 92.2% → 91.2% |

**A 9× reduction in the failure that matters**, and still no decay.

## Which families changed

| family | before | after |
|---|---|---|
| quote (reported speech) | **0.0%** | **100%** |
| contra (self-contradiction) | **0.0%** | **100%** |
| neg (prohibition) | 66.7% | **100%** |
| retract | 33.3% | 67.5% |
| base / comp / noise | 87.5 / 47.9 / 66.7 | 87.6 / 48.1 / 67.5 |

Every family the gate has a rule for went to **100%**. The three that
barely moved are not gate failures — they are **parser coverage** gaps,
where tier 0 emits nothing or the wrong frame and there is nothing for a
veto to fix: `base-a3` ("advance two metres"), `comp-a2`, `retract-a2`.

## The residue was one sentence

Every false actuation printed during the 36-minute run was the same
case: `noise-a6`, the bare word **"forward"**, driving 1 m *"by
default"*. Not a class — one underspecified-command hole, firing each
time it came round.

That is now closed by a general rule, `invented_magnitude`: **a frame
carrying a distance or angle the utterance never mentioned is refused.**
Verified both directions at gate level — `"forward"` and bare `"drive
forward"` blocked; `"2 metres"`, `"half a metre"`, `"a metre"`, `"two
metres"`, `"a quarter turn"`, `"turn around"`, coordinates and stops all
still pass. It is the same defect as the units bug fixed the same week:
inventing a number nobody said.

⚠️ **The rule landed AFTER this run**, so the 2.4% above does not include
it. A re-run should be lower; that number does not exist yet and is not
claimed here.

## What made the comparison meaningful

langsoak runs with no key, so it takes the offline keyword ladder — which
was still ungated. Re-running without changing that would have left the
22% untouched and taught us nothing. The ladder is now gated at the
utterance level: the intent rules are properties of the sentence, not of
the frame, so the question "may anything move for this sentence?" is
asked once before the ladder picks a verb.
