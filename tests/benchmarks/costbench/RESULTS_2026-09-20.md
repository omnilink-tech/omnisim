# What one robot task costs, measured

**Task:** a Husky drives forward 2 m, turns 90°, drives back 2 m. One cycle,
three commands, repeated for 24 hours. The most boring possible robot job:
nothing about the 7,000th repetition needs judgement the first did not.

## Result

| architecture | 24 hours |
|---|---|
| a model decides every command | **$82.04** |
| one instruction, deterministic loop | **$0.003** |
| fully deterministic | **$0.00** |

## Which model, and why the ratio is the claim

$82.04 is the CHEAPEST tier. The same measured workload -- 26,916 commands,
150.5M input + 2.26M output tokens -- across the engines the platform offers,
at the list rates in `COSTS.md`:

| engine | 24 h, a model decides each command |
|---|---|
| Gemini 3 Flash (measured on) | **$82** |
| GPT / Claude Haiku 4.5 | **$162** |
| Claude Sonnet 4.6 | **$485** |
| Claude Opus 4.7 | **$2,427** |

⭐ **The ratio against one-instruction-plus-a-tree is 26,916x on every row.**
Identical for Flash and for Opus, because the saving is not a price
difference -- it is not making 26,915 of the 26,916 calls. Model choice moves
the absolute by 30x and the multiple by nothing.

That is the durable form of the claim. It survives a price cut, a faster
model, and an argument about which engine is a fair comparison. The $82 does
not survive any of them.

⚠️ Latency differs by model, so the WORK is held constant, not the clock: a
slower model takes longer than 24 h to issue the same 26,916 commands, it
does not become cheaper. Token counts are Gemini's tokenizer; another model
will differ by perhaps 10-20% on the same text, which moves the absolutes and
not the ratio.

## What was measured, and how

| quantity | value | source |
|---|---|---|
| prompt per command | **5,592 tokens** | Gemini `countTokens` on the payload the bridge actually sends |
| system instruction | 9,066 chars | captured verbatim from the bridge |
| tool definitions | 17 | same capture |
| output per command | **84 tokens** | `usageMetadata` over 3 real calls |
| inference latency | **1.88 s** | wall clock, same 3 calls |
| robot motion per cycle | **4.0 s** | costbench deterministic arm |
| deterministic token use | **0** | 400 checked steps + 9 commands, no key present |

Cycle = 4.0 s motion + 3 × 1.88 s inference = **9.6 s** → 8,972 cycles/day.
Per command $0.00305 → 3 × 8,972 × $0.00305 = **$82.04**.

The prompt was captured by standing in for Ollama on port 11434 and recording
what the bridge posted, so it is the real payload rather than a reconstruction.
Model `gemini-2.5-flash` via Vertex, priced at the Gemini Flash list rates in
`agents/production/husky_maze/docs/COSTS.md` ($0.50/M in, $3.00/M out).

## The number behind the number

**5,592 tokens in, 84 out.** 98.5% of every bill is a prompt that is byte-for-byte
identical on all 26,916 commands of the day, sent to obtain an answer that is
also identical. That, not the total, is the argument: you are paying to
re-explain the robot to a model that has no memory of the last 26,915 times.

## ⚠️ Corrections to earlier estimates

An earlier projection in this project said **$445/day**. It was wrong by 5.4×.
It borrowed 35,730 tokens/turn from `COSTS.md`, which measured the *husky_maze
agent* — an LLM solving a maze, carrying far more accumulated history. The
Husky *bridge chat* prompt is 5,592 tokens. Measuring beat guessing by a factor
of five, in the conservative direction.

## What this does NOT measure

- **Platform overhead.** This prices the model call. The OmniLink platform adds
  its own guardrails and memory to the prompt, so routed through the platform
  the figure is higher, not lower.
- **Caching.** The 5,592-token prefix is static and is a textbook cache
  candidate. `COSTS.md` puts naive caching at ~20% off; an explicit prefix cache
  would cut far more. Nothing here is cached.
- **Thinking time.** The cadence assumes commands issue back to back.
- **One model, one day.** `gemini-2.5-flash` at list price on 2026-09-20.
